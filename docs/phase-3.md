# Phase 3: creative direction and image review

The user requests two routes: manual generation and a free API option, with flexible styles per project. Work stays on main, each modified file gets its own commit, and completed features get a separate checkpoint. No pushes.

Foundation: editable style controls, deterministic local prompt assembly, immutable prompt versions with frozen research/reference context, downloadable prompt/reference packs, persistent batches of 1-4 images, side-by-side review, explicit approve/reject decisions and review notes. Imported artwork is clearly labelled; it must never be presented as generated by Variance.

Implemented API adapter: Cloudflare Workers AI `@cf/black-forest-labs/flux-2-klein-4b`. Reference inputs are explicitly limited to four and resized below 512 pixels per side. Output sizes follow the selected aspect ratio. No fallback provider, automatic retries, or billing changes.

## Setup and use

1. Select references in Research & references, then open Creative direction.
2. Choose any style, medium, palette, composition and identity constraints. Assemble locally, edit the prompt, and save a version. Versions freeze the source context and reference identities. Changing direction controls requires a fresh assembly.
3. In Image studio select Manual generation or API generation and a saved prompt; create 1–4 variations.
4. Manual: download the prompt/reference ZIP, generate with your preferred tool, then import each result (PNG/JPEG/WebP, up to 8 MB).
5. API: configure `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_TOKEN` (Workers AI permission) in the ignored root `.env`. Confirm the account uses **Workers Free**, then set `CLOUDFLARE_FREE_PLAN_CONFIRMED=true` and restart. The app cannot inspect billing plans. Workers Paid can charge overages; do not use it for this free-only workflow.
6. Compare results, inspect full-size images, approve/reject/reset and save notes. Reviews persist locally with revision conflict detection.

## Queue and recovery

Run one backend process. Queued API batches persist in SQLite and resume when it starts. In-flight batches become interrupted after restart and are never resent automatically because the provider might already have processed them. Partial results remain available. Failure messages omit provider payloads and tokens. Start a new batch explicitly to try again. Archived projects are checked before each provider call and each saved image. A call already sent cannot be recalled.

Batches are idempotent per request key. The UI reuses the key when retrying a failed submission with unchanged settings. Reference/image storage uses normalized, content-addressed PNGs, and pack export preserves removed references through immutable snapshots. Back up both `data/studio.sqlite3` and `data/references`, including its artwork directory. Prompt drafts are saved only when **Save new version** is clicked; unsaved edits are lost when leaving the editor.
